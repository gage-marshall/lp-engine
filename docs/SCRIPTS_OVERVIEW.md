# Scripts: complete map (status 2026-10-12)

What "scripts" are in LovePlus+: SBIN bytecode resources in `tmx_event.arc` (1,236 scripts, 16,332 entries). Everything needed to run, choose and port them is documented below, with how each part was validated and what is still approximate.

## 1. Format, VM, ids, directory (done, validated on the whole corpus)
- Bytecode, opcodes, string table, variables, call/return/deferred-return semantics: `docs/SCRIPT_VM.md`, reference VM `tools/lpvm.py`, tracer `tools/event_trace.py`. Validated: all 16,332 entries run with 0 bad opcodes / 0 faults; 41,026/41,042 jumps land on instruction boundaries; dialogue checked against the emulator.
- Script ids: `id = heroine byte pattern + key` (heroine = top byte: 0xa0/0xa4 Manaka, 0x58/0x5c/0x5f Rinko, 0x08/0x0c/0x0f Nene; class 0x80 = heroine-independent). Directory `tmx_event.arc` entry 899 maps every id to (slot, script, entry); multi-part events continue with id+1, id+2 (`...3400`, `...3401`, `...3402`) driven by `GameFlow_RunMainLoop`.

## 2. Commands: what a script can do (`docs/SCRIPT_COMMANDS.md`, `docs/SCRIPT_TASKS.md`)
- All 393 commands used in scripts are listed with name, arguments and meaning (`tools/cmd_ref.py`; CSV `fid/script_command_names.csv`). Share of the 248,931 script calls by confidence: V (verified against emulator/content) 35.3%, H (handler + argument statistics agree) 38.3%, M (handler clear, argument meaning inferred) 22.1%, L 3.1%, E (exact native call chain recorded, meaning inferred from function names) 1.1%.
- Live ground truth: `tools/play_monitor.py` hooks every handler and logs the real `(cmd, args)` stream (stack ABI: ctx `0x21415b8`, `+0x10cc` sp, `+0x10d4` stack, `+0x10c0` command id; several ids share one handler address). Example verified stream of a heroine scene: `f [588,20]` motion blend, `5c [voice,7]`, `5d [582,20]` queued motion, `34 [mood]`, `136 [mood]`, `44 [1]` + `1` (wait/yield).
- Waiting semantics: `docs/SCRIPT_TASKS.md` (116 task kinds, completion predicates: countdown, transform flag, fades idle, msgbox closed, overlay predicates). The 17 previously "faulting" commands are the dream-scene overlay (ov37) command set, dispatched through one stub on the command id; `ctx+0x10bd = 0x87` keeps the script suspended, `ctx+0x10c4` is `acc`.

## 3. Which script plays when (event selection) (`docs/EVENT_SELECTION.md`, `docs/CONDITIONS.md`)
- Entry: `EventState_Initialize` (0x2056248) takes the id from the event *session* (`0x2156898`): a 36-stage resolver pipeline (`MicSession_Clear`, table 0x210b8f0 = `{allowed-context mask, kind, handler}`), first stage with a non-zero result wins. The session mask comes from the clock and the **player's schedule** (予定入力: four periods per day, activity code per period, partner type). Validated by hooking: on all 100 headless + 41 hand-played script starts the session mask is a subset of the winning stage's mask and the stage kind equals the table's.
- Candidate lists are **data**: `arc/tmx_tbin.arc` (688 TERM_BIN files, 2,920 records; format in `tools/term.py`): record = `{event id, priority, used-flag, 3 OR-groups of (op, a, b)}`, evaluated by the native op table (237 entries at 0x21246c8, 107 ops used; vocabulary in `docs/CONDITIONS.md`, generated by `tools/cond_ops.py`). Validated: parser consumes all files exactly; 2,478/2,920 records' used-flag is set by their own script (cmd 0x55); 100% of the ids started by stages 18 and 29 are term records. Ten per-heroine tables list which files feed which stage/queue (stride 8 `{count, u16 file list}` at 0x21071d0, 0x2107338, 0x210738c, 0x2107594, 0x2107678, 0x2107b00, 0x210b308, 0x210ec18, 0x210ec30, 0x21122ac; 310 files referenced from these; the rest use other lookup structures).
- Table-backed stages (31 `Schedule_ResolveRuleMessage`, 27 `TextEvent_*`, text routes `SceneRoute_SelectTextRoute` 15 tables) and calendar-rule stage 12: id tables indexed by `[heroine][relationship stage 0..2]` (`tools/event_routes.py`).
- **Exact executable specification (verified against the real ARM code).** `tools/cond_eval.py` (all 107 condition ops + whole-file `CondList_CollectPassingRecords` semantics), `tools/stage_eval.py` (all 36 stage handlers), `tools/pipeline_eval.py` (`MicSession_UpdateTimed`, `MicSession_Clear`). Method: Unicorn runs the handler's own machine code (`tools/cond_oracle.py`), every call leaving it is answered by a deterministic mock game state (`tools/cond_mock.py`, leaf arities estimated from the callee code by `tools/arity.py`), the Python port reads the same leaves by name. Results: every op bit-exact over 20-40 mocked states and every observed `(op, a, b)` (this found and fixed many wrong summaries: set/clear polarity of ops 13/14/24/25/107/108, ops 59-70 compare stat *ranks* with `a`, ops 40-48 heroine phase sets, 74/75 tail-calls, 118 argument passing, ...); 6,612 whole-file evaluations 0 mismatches; every one of the 36 stages 0 mismatches over 38,304 states each (1.38M total, up to 22 distinct leaf-call paths per stage; RAM state is reset between runs, timeouts excluded).
- Stage reference: `docs/EVENT_STAGES.md`; ROM tables used by the stages: `tools/stage_tables.py` -> `content/engine/stage_tables.json`; RNG: `Rand_Next` 64-bit LCG seeded from the RTC (`docs/EVENT_STAGES.md`).
- Export for the port: `tools/event_export.py` writes `content/engine/event_selection.json` (stages, text routes, all condition records, op handler table).

## 4. Tools (all regenerate from the user's own ROM data; nothing ROM-derived is committed)
`tools/play_monitor.py` (play + log), `tools/event_sampler.py` (headless multi-day sampler), `tools/term.py`, `tools/cond_ops.py`, `tools/save_fields.py`, `tools/event_routes.py`, `tools/event_export.py`, `tools/cmd_ref.py`, `tools/task_ref.py`.

## 5. What is not covered (bounded, none affects which script plays)
1. **Leaves below the verified layers.** The condition ops and stage handlers are exact; the *values* returned by the leaves they call are only documented, not re-derived: calendar rules (tabulated by running the native module over every code and year: `CALENDAR.md`; 115 fixed-date codes, 16 weekday/moving-holiday codes), scoped flag ids (`CONDITIONS.md`), schedule state getters, save-record getters (`SAVE_RECORD.md`), the id-producing leaves (`MapEvent_GetVariantValue`, `MapEvent_CheckWorkState`, `UiInput_*`, ...; tables in `stage_tables.json`) and the queue loaders. A port that wants bit-exact replays must reimplement those leaves (their decompiles are in `fid/decomp/`).
2. **Commands.** 3.1% of calls (L) and 1.1% (E) are described only by their native effect chain; 22.1% (M) have measured/inferred argument meaning (e.g. units of fade/blend frames); the wait tick was measured (`tools/cmd_timing.py`: 3.8 frames in the 3D heroine scene), other unit claims are inferred from handler code and argument statistics.
3. **Heroine save record**: 72 accessor-derived fields; the long tail of single bytes at +0x105..+0x172 is typed but unnamed.
4. **RNG**: the policy is fully known (`Rand_Next`, RTC seed); exact replays of a recorded run additionally need that run's RTC value at boot.
