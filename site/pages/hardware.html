Chapter 10

The hardware edges

Where the game meets the hardware, small facts matter. A touch position that's slightly off makes every tap miss. A bit read from the wrong place means the lid never closes. Each edge here was measured in the real game first, then answered the same way in lp-engine.

The touch screen

The ARM7 samples the touch panel and leaves the result where the game reads it each frame (Touch_Update). One detail cost a long search: when the pen lifts, the sample keeps the last pressed position and only clears the "touching" flag. It doesn't go to (0, 0). The room depends on it. Its tap handler runs a second hit test on the release, at the position that sample gives. Report (0, 0) on release, as an emulator might, and every tap in the room misses.

In lp-engine, the mouse on the right-hand screen is the stylus.

Handwriting

The profile screen asks you to write your name by hand, and recognises it with a licensed third-party handwriting engine that lives in overlay 6 with the profile screen (Ov06ProfileDlt_RunProfileScreenStateMachine). lp-engine runs it as the game's own code, so it recognises the same strokes the same way.

The microphone

LovePlus+ listens at times, and overlay 5 holds a speech-recognition engine for it. The game uses the SDK's microphone library, which talks to the ARM7 over PXI tag 9:

  • One sample (MIC_DoSampling): the ARM7 reads the microphone once and leaves the value in shared memory.
  • Auto sampling (MIC_StartAutoSamplingAsync): the game hands over a buffer, its size and an interval, and the ARM7 fills the buffer as time passes. It reports the last address written, wraps around if asked to loop, and otherwise stops and reports the buffer full.

Samples come in four formats: 8 or 12 bits, signed or unsigned. A 12-bit sample sits in the top 12 bits of its 16. The SDK's own example reads the top byte for a quick level, and getting that wrong would scramble every sample.

lp-engine answers the same protocol. The microphone opens only when the game first listens (that's when your computer asks for permission), and Sound > Use the Microphone switches it off. Samples are taken from your microphone at its own rate and resampled to the interval the game asked for. An engine test drives the game's own microphone functions and checks every sample in all four formats.

The lid

Closing a DS puts it to sleep. The game checks for this once a frame in PowerMgr_Process: it reads bit 15 of the key word the ARM7 shares, counts the frames the lid has been closed, and after nine of them calls PM_GoSleepMode. On the DS, that call doesn't return until the lid opens. The clock keeps running while the DS sleeps, so the game wakes into the right time of day.

In lp-engine, minimizing the window closes the lid, and so does Game > Close the Lid. The game reaches its sleep call exactly as on the DS, and the engine stops running the game until the lid opens again. Before this was worked out, the lid bit was being set in the wrong place, bit 7 instead of bit 15, and the game never noticed the lid at all.

Buttons

Ten of the buttons come through a hardware register the ARM9 reads directly. X, Y, the lid and the pen state come through the ARM7's key word instead, which is why the lid lives next to the buttons. lp-engine maps them all to keys you can change, and to gamepads.

Power

The power manager on the ARM7 also powers the screens. The game can switch them off and on (PM_SetLCDPower), and it turns the display output off before it does and back on after.

The cartridge

On the DS, the game reads its files from the cartridge on demand and saves to a separate backup memory chip. lp-engine serves the reads from the files it extracted from your copy, layered under the translation's files, and emulates the backup chip with the 256 KB save file from chapter 6.

Wireless, which isn't there

Talk Mode, card exchange, pass-by communication, save transfer and the regional capsules all need a second DS. They run on the wireless library, which needs its ARM7 half to be running. Before it starts, the game asks whether that half is ready (PXI_IsCallbackReady), and WM_Init fails if it isn't.

lp-engine answers honestly: wireless isn't ready. In practice, though, those features never get that far. lp-engine's port of the title menu doesn't include the wireless branches, and before this was handled, picking one faded to a white screen and stayed there. Now each wireless choice shows a short notice and returns to the menu page it came from, the way the game's own single-player branches end.
